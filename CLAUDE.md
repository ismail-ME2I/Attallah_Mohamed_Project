# Mohammed Attallah — Personal Brand Website
# Claude Code Project Instructions

## 1. PROJECT IDENTITY

This repository contains the website project for **Mohammed Attallah**, an Automation Technical Leader at Schneider Electric.

The website is a **premium personal-brand ecosystem**, not simply a portfolio, CV website, course marketplace, or corporate profile.

The central brand is:

**Mohammed Attallah**

The website presents him primarily as:

- Automation Expert
- Technical Leader
- Educator

It also introduces:

- Technical Consulting & Advisory
- Easy Automation Academy

---

## 2. PRIMARY OBJECTIVE

Build a premium, credible, technically sophisticated personal website that makes Mohammed immediately feel:

> "This is not just a website for my course — this is a serious premium platform representing me as an automation expert."

The website must communicate:

- technical authority
- real-world automation experience
- leadership
- credibility
- education
- practical knowledge
- professional maturity
- precision
- confidence
- premium positioning

The design must feel intentional and editorial rather than template-driven.

---

## 16. DESIGN SYSTEM

Follow D06.

Baseline colors:

- Primary background: `#F6F7F8`
- Secondary background: `#EDEFF1`
- Dark Project Proof: `#14171A`
- Card surface: `#FFFFFF`
- Primary text: `#1B1F23`
- Secondary text: `#4A4F55`
- Muted text: `#7A7F85`
- Inverse text: `#F6F7F8`
- Inverse muted: `#B8BCC0`
- Primary accent: `#AA5E2B`
- Accent hover: `#915125`
- Subtle border: `#DFE2E5`
- Dark border: `rgba(255,255,255,0.12)`
- Focus ring: `#B4642E`

> **Note (approved accessibility adjustment):** Primary accent was adjusted from `#B4642E` to `#AA5E2B` (and the hover value from `#9C5527` to `#915125` by the same proportional shift) to satisfy WCAG AA 4.5:1 text contrast against `#F6F7F8`, while preserving the intended copper/amber visual identity. Approved during Sprint 01.

Do not introduce a second accent color without explicit approval.

## 19. RESPONSIVE REQUIREMENTS

The website must work properly across:

- large desktop
- standard desktop
- tablet
- mobile

Mobile principles:

- approximately 20px side margins
- 16px minimum body text
- 44px minimum touch targets
- full-width mobile CTAs where appropriate
- accessible navigation overlay
- Hero stacks vertically
- Hero image becomes a controlled image strip
- Project Proof image appears before text on mobile

Do not simply shrink the desktop layout.

---

## 20. ACCESSIBILITY

Minimum requirements:

- semantic HTML
- one clear H1
- proper heading hierarchy
- keyboard navigation
- visible focus states
- accessible buttons and links
- meaningful alt text
- reduced-motion support
- sufficient color contrast
- minimum 44px touch targets
- correct navigation landmarks

Do not sacrifice accessibility for visual effects.

---

## 21. PERFORMANCE

Prefer:

- responsive images
- WebP / AVIF where appropriate
- lazy loading below-the-fold images
- eager loading for critical Hero imagery
- minimal font weights
- CSS transforms and opacity for animation
- lightweight dependencies

Avoid:

- unnecessary libraries
- heavy animation packages
- autoplay video
- oversized assets
- unnecessary network requests
